# SEO分析レポート: ドメイン戦略 & 検索パフォーマンス改善

**作成日**: 2026-04-01  
**対象サイト**: ph-document.com  
**対象期間**: 2026年3月（Search Console 28日間データ）

---

## 1. ドメイン戦略の判断

### 結論: 現在のサブディレクトリ方式（/en/, /ja/, /ko/）を維持すべき

言語ごとに別ドメイン（例: ph-document.jp, ph-document.com）やサブドメイン（ja.ph-document.com）に分離することは**推奨しない**。

#### 理由

| 観点 | サブディレクトリ（現状） | 別ドメイン/サブドメイン |
|------|------------------------|----------------------|
| ドメインオーソリティ | 1ドメインに集約（有利） | 分散して各ドメインが弱体化 |
| Google推奨 | 公式に推奨される方式 | 大規模サイト向け |
| 被リンク効果 | 全言語で共有 | 言語ごとに別カウント |
| 運用コスト | 低い（1つのCloudflare設定） | 高い（複数のDNS/SSL/設定） |
| Search Console | 1プロパティで管理可能 | 言語ごとに別プロパティ |

**特に重要**: 現在の月間95クリック規模では、ドメインパワーの分散は致命的。サブディレクトリ方式で1つのドメインに集約し続けるのが最善。

別ドメインが有効なケース（今回は該当しない）:
- 各市場で独立したブランドを持つ大企業（例: amazon.co.jp vs amazon.com）
- 月間数万クリック以上の規模がある場合
- 各言語で全く異なるコンテンツを提供する場合

## 3. 検索パフォーマンス低迷の根本原因

### 原因1: SEO設定の頻繁な変更（最大の問題）

**直近1ヶ月でSEO関連ファイルに15回のコミット。**

特に問題なのは hreflang タグの扱い:

| 日付 | 変更内容 | 影響 |
|------|---------|------|
| 3月中旬 | hreflang クロスリンク追加 (#158) | Googleにマルチ言語シグナル送信 |
| 3/29 | hreflang 全削除 — 言語サイト独立運用へ (#159) | Googleにシグナル撤回 |
| 3/29 | sitemapからもhreflang削除 (#163) | 完全にhreflang消失 |
| 4/2 | hreflang 再追加 (#171, #172) | 3日で方針転換、Googleに矛盾したシグナル |

**Googleのクローラーは変更を即座に反映しない。**  
インデックスの反映には2-4週間かかる。数日単位でSEO構造を変更すると:
- クロールバジェットが浪費される
- Googleがサイトの「正しい状態」を判断できなくなる
- 一時的にランキングが不安定化する

### 原因2: sitemap.xml の不整合

`public/sitemap.xml`（リポジトリ内の静的ファイル）には hreflang エントリが**含まれていない**。

`scripts/prerender.ts` の `generateSitemap()` は hreflang を含む sitemap を生成する機能があるが、ビルド時に `dist/` に出力される。もし Cloudflare Pages にデプロイされる sitemap が `public/` の静的版であれば、hreflang がサイトマップ経由でGoogleに伝わっていない可能性がある。

**確認方法**: `curl -s https://ph-document.com/sitemap.xml | grep xhtml` で本番のsitemapにhreflangが含まれているか確認する。

### 原因3: 旧URLの残存インデックス

Search Console で以下のようなプレフィックスなし旧URLがまだ表示されている:
- `/psa-birth-certificate-cost/` (572インプレッション)
- `/cenomar-guide/` (107インプレッション)  
- `/gaimen-kirikae-guide/` (107インプレッション)

これらは301リダイレクトが設定済みだが、Googleのインデックスからの完全な移行には数週間-数ヶ月かかる。その間、旧URLと新URLが検索結果で競合し、シグナルが分散する。

### 原因4: SPAフォールバックの言語不整合

`_redirects` の最終行:
```
/*  /index.html  200
```

これにより、プリレンダリングされていないURLすべてに英語の SPA シェル（`<html lang="en">`）が返される。`/ja/*` にアクセスした場合でも、Googlebotが最初に受け取るHTMLは英語メタデータを持つシェルの可能性がある。

プリレンダリング済みページであればこの問題は回避されるが、クロール時のタイミングや条件によっては正しい言語のHTMLが返らないリスクがある。

### 原因5: CTR改善の余地

平均掲載順位8.2で CTR 1.6% は低い。主な要因:
- **タイトルタグの訴求力不足**: 検索結果に表示されるタイトルがクリックを誘引する内容になっていない可能性
- **メタディスクリプションの最適化不足**: 検索意図に合った説得力のあるディスクリプションが必要
- **リッチリザルト非表示**: FAQスキーマやHowToスキーマが適切に認識されていない可能性

## 4. 優先順位付き改善推奨事項

### 最優先: SEO変更の凍結（即日実施）

**今後4-6週間、SEO構造に関するコード変更を一切行わない。**

これが最も重要。現在の状態（hreflang再追加済み）をGoogleに安定して認識させる時間が必要。

具体的に凍結すべき項目:
- hreflang タグの構造
- canonical URL の設定
- sitemap.xml の構造
- robots.txt
- リダイレクト設定
- JSON-LD 構造化データの構造

### 優先度2: sitemap.xml の確認と修正

1. 本番環境の `sitemap.xml` を確認: `curl -s https://ph-document.com/sitemap.xml | grep xhtml`
2. hreflang が含まれていない場合、`npm run build` でプリレンダリングを実行し、生成された `dist/sitemap.xml` を `public/sitemap.xml` にコピー
3. これは「新しい変更」ではなく「既存の意図した設定の反映漏れ修正」なので、凍結期間中でも実施すべき

### 優先度3: Search Console での旧URL管理

1. Search Console の「URL検査」で主要な旧URL（プレフィックスなし）のインデックス状態を確認
2. 301リダイレクトが正しく機能していることを確認
3. 必要に応じて「URL削除」ツールで一時的な非表示を申請
4. Google Search Console の「インデックス > ページ」レポートで、除外されているURLや問題のあるURLを確認

### 優先度4: lastmod の正確化（凍結期間後に実施）

- `scripts/prerender.ts` の `SEO_DATE_ISO` がすべてのURLに同一日付を適用している
- 各ページの実際の更新日を反映すべき
- Googleが更新されたページを優先的にクロールするようになる

### 優先度5: CTR改善のためのタイトル/ディスクリプション最適化（凍結期間後に実施）

特にインプレッション対比でCTRが低いページ:
- `/en/psa-birth-certificate-cost/`: 868インプレッション / 4クリック（CTR 0.5%）
- `/ja/gaimen-kirikae-guide/`: 344インプレッション / 10クリック（CTR 2.9%）

これらのタイトルとディスクリプションを、検索意図に沿った訴求力のある内容に改善する。

## 5. 今後の注意点

### SEO変更のルール

1. **変更は月1回まで**: SEO構造の変更は月に1回のリリースにまとめる
2. **効果測定期間を設ける**: 変更後は最低4週間、Search Console でデータを観察してから次の変更を検討
3. **A方針を決めたら貫く**: hreflangの「あり/なし」のような根本的な方針は、一度決めたら最低3ヶ月は変更しない
4. **データに基づく判断**: 「〜したほうがよさそう」ではなく、Search Console のデータで問題を確認してから変更する

### 監視すべき指標

| 指標 | 現在値 | 目標（3ヶ月後） |
|------|-------|---------------|
| 全体CTR | 1.6% | 3.0%+ |
| 日本CTR | 4.6% | 6.0%+ |
| 全体クリック数 | 95/月 | 200+/月 |
| 平均掲載順位 | 8.2 | 6.0以下 |
| 旧URLインプレッション | 多数残存 | 0（完全移行） |

### 回復の見通し

3/29のhreflang削除の影響は、4/2の再追加後、**2-4週間で回復が始まる**見込み。ただし完全回復には6-8週間かかる可能性がある。この間にさらなる変更を加えると回復が遅れる。

## 付録: 現在のサイト構成概要

- **フレームワーク**: Vite + React (SPA) + プリレンダリング
- **ホスティング**: Cloudflare Pages
- **言語**: EN (30+ ページ), JA (40+ ページ), KO (5 ページ)
- **i18n方式**: サブディレクトリ (`/en/`, `/ja/`, `/ko/`)
- **プリレンダリング**: `scripts/prerender.ts` で静的HTML生成
- **hreflang**: prerender時にHTML内とsitemap.xmlに注入（4/2再追加済み）
- **リダイレクト**: `public/_redirects` で旧URL→新URLへの301リダイレクト設定済み
